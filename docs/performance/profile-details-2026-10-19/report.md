# 个人详情展开/收起性能验证

关联：https://github.com/fahnzjan/bojian-mobile/issues/18

设备：PJD110，Android 真机，Profile/AOT 模式，Flutter 3.47.6。先测原实现再改代码，使用同一个测试脚本复测。

## 测试资料与场景

固定资料包含 ID 100000、广东省属地、注册时间、长个人简介、本地 HTTP 提供的固定 PNG 头像。测试断言紧凑头部显示“ID：100000 / IP：广东”，全屏显示“IP属地：广东省”。不访问真实账号或远端接口。

场景：8轮点击展开/收起（首轮单列，后7轮聚合），另测下拉展开及详情滚动后收起。采用 fullyLive 策略，以 FrameTiming 的 buildStart 时间戳归入操作窗口；每个窗口覆盖操作和其后650ms，含收尾帧。不是 Debug 模式或100ms跳步推进动画的结果。

最初探索使用的资料未包含 IP 属地，用户指出后已补齐并重测原实现；缺少属地的探索结果不作为最终对比。

## 结果

单位 ms，P95 为本次采样的第95百分位。超预算指 build/raster 任一超过16.67ms，不等于操作系统统计的实际丢帧数。

| 场景 | 构建P95 原/新 | 绘制P95 原/新 | 超16.67ms帧 原/新 |
|---|---:|---:|---:|
| 首次展开 | 4.90 / 8.73 | 7.84 / 11.65 | 0 / 0 |
| 首次收起 | 6.30 / 4.63 | 9.55 / 10.25 | 0 / 0 |
| 连续展开（7轮） | 8.52 / 7.08 | 10.57 / 11.87 | 0 / 0 |
| 连续收起（7轮） | 7.67 / 4.87 | 10.93 / 10.28 | 2 / 0 |
| 下拉展开 | 10.25 / 8.01 | 9.02 / 10.65 | 0 / 0 |
| 滚动后收起 | 8.55 / 6.60 | 10.55 / 12.42 | 0 / 0 |

原实现最高绘制耗时18.048ms；最终复测所有场景均无超过16.67ms帧。改善主要来自连续展开/收起与拖拽的构建耗时，首次展开和部分绘制P95并未逐项改善，不能据此声称所有指标都变快或保证任何条件下都不卡。

设备采用动态刷新率，测试期间临时设置的首选120Hz不等于系统实际一直按120Hz渲染；采样期间系统实际渲染以60Hz为主。原始JSON中 over_refresh_budget 只是按开始时报告刷新率计算的参考值，不作为120fps/实际丢帧结论。临时首选模式在测试后清除，恢复原先的自动设置。

## 修改与自审

- 将详情布局、源资料快照和固定尺寸模糊背景移出逐帧构建范围；动画只更新裁切与透明度。
- 固定背景尺寸，避免动画中反复改变滤镜布局；使用 RepaintBoundary 隔离可复用绘制。
- 下拉动画仅重建头部 Sliver，不再每帧重建整个个人页、标签与列表。
- 保留详情信息、头像/昵称形变、拖拽横条、编辑、返回及减少动画设置。

依据项目 Flutter 架构、组件测试和布局技能进行自审（非独立审查）：store仍驱动资料变化，缓存不冻结编辑后的资料；边界尺寸有限，扩展区域保留裁切；Tab保留、刷新、退出及返回路径不变。53项相关回归通过，含IP属地、窄屏、大字体、深浅色与减少动画。静态分析通过。结论：本次范围通过。

## 背景衔接修正

用户指出背景画幅切换容易被误认为卡顿。复查发现头部按自身高度裁切照片/渐变，详情按固定全屏高度裁切，导致展开首帧和返回时背景突变。现在两处统一采用屏幕尺寸的画布并固定顶部锚点，动画只展开裁切范围；滚动后打开时锚点随区域连续移动。保留全屏详情的内容布局。

新增像素回归逐一比较打开首帧、展开中、展开结束、收起中和返回后的裸露背景边缘，包含静止、滚动、下拉和实际底部导航入口，资料含IP属地。把旧实现临时恢复后前三个场景均失败，首帧通道差值可达53；修正后容差限制为2，确认测试能发现实际突变。

第一版只统一画幅，真机首次展开出现5个超16.67ms帧，因此继续将模糊滤镜放到240px源图上处理，再等比放大；按画布缩放比例换算sigma，保持32逻辑像素的视觉模糊半径，避免处理整屏滤镜。第一版数据保留在background-first-pass-with-ip.json。

最终复测数据保留在background-continuous-with-ip.json（同一PJD110，资料包含属地）。本轮设备报告90Hz，期间帧数反映动态刷新，不能与前轮逐帧直接等同。首次展开绘制P95由第一版17.38ms降至11.93ms；连续收起绘制P95为9.17ms，下拉展开为9.24ms。本轮首次展开仍有1帧、连续展开有2帧超16.67ms；其余场景为0，不能声称零慢帧或保证90/120fps。本次修复针对背景裁切/明暗突变，并控制模糊处理开销。

最终自审（非独立审查）：依据Flutter架构技能检查本次只涉及展示层、未引入业务或数据缓存；依据组件测试技能确认像素用例在旧实现失败，修复后含实际导航入口及IP属地的57项回归通过；依据布局技能检查OverflowBox始终使用有限屏幕尺寸、顶部锚点一致、外层ClipRect裁切，保留窄屏/横屏/大字/减少动画及编辑返回。小图模糊按实际放大比例换算半径，头像/资料变更仍由store正常更新。静态分析通过。本次背景衔接修正自审通过；保留上述帧耗时限制，不宣称独立审查。未提交、未推送，Issue保持开放。

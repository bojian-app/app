## 真机收回复现与修正

按用户要求，使用 PJD110 上正常 `lib/main.dart` Release 页面和现有账号资料，包含头像、IP属地、注册时间、个人简介及动态卡片。正式采样通过 UIAutomator 确认已打开包含 IP 属地的详情后，再点击关闭；返回后确认紧凑 ID/IP 恢复。未打开独立测试页，未修改用户资料或提交任务。

同次操作采集 scrcpy 录像及 Perfetto FrameTimeline，视频为464×1024，设备1440×3168。比较白色面板到位的最后几个位置：

| 场景 | 面板末段位置（视频像素） | 最后一步 |
|---|---|---:|
| 修改前，下拉后关闭 | 531 → 522 → 517 → 513 → 462 | 51px，约40逻辑像素 |
| 收回修正后，下拉后关闭 | 487 → 475 → 468 → 463 → 462 | 1px |
| 收回修正后，点击简介后关闭 | 496 → 482 → 472 → 465 → 462 | 3px |

原因：详情收回的目标还是下拉拉伸后的头部；底层头部的回弹又与路由退出衔接，最后出现40逻辑像素的高度错位。修正为详情完全遮挡源页后提前恢复头部原高，头像 Hero 和裁切区域均返回原高。等待 `route.completed` 后才结束本次打开状态，避免在 pop 开始时提前回弹或重复打开。

新增回归在原实现明确报错：期望头部347，实际387，差40；修正后验证遮挡下恢复及收回末帧对齐。

真实采样原始视频、完整系统追踪保留于本机临时目录；仓库中的 `real-collapse-before.json`、`real-collapse-after-pull.json`、`real-collapse-after-click.json` 只记录位置和帧时间数据，不包含个人图片或简介内容。后两份数据明确标记为追加滚动顶栏改动之前的收回修正版。

本轮 FrameTimeline 分别有29/31/31个应用表面帧，Late Present为6/8/7，涉及预测误差、SurfaceFlinger、Display HAL和Unknown等分类，没有App Deadline Missed标记。录屏和系统追踪存在采样开销，帧呈现分类不等同Flutter构建/绘制耗时。结论限于已确认的尾帧几何跳变消除，不据此承诺零慢帧或90/120fps。

- 顶部底色、前景色随滚动变化，资料内容在移动的身份区下方裁切；部分滚动时打开详情会保留起始底色范围并连续过渡。
